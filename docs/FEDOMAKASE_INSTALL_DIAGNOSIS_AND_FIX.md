# Fedomakase Install & First-Boot Diagnosis and Fix (Acer Googlebook 14 `Moonstone`)

## 1. Observed Symptoms on First Boot

After completing the Fedomakase (Fedora 44 + Omarchy Quattro Hyprland) installation on the Acer Googlebook 14 (`Moonstone`, `GP714-91N`, Intel Panther Lake `x86_64`) and booting into Slot B:

1. **Password screen (`sddm-greeter-qt6`) appeared briefly (~1 second)**.
2. **Hyprland displayed a configuration warning/error banner** stating that Hyprland was using an autogenerated config (`"Warning: You're using an autogenerated config! Edit the config file to get rid of this message."`), indicating Omarchy's Lua configuration was missing or not loaded.
3. **The session kicked out / transitioned to a black screen with a mouse cursor** and no QuickShell top bar, wallpaper, or keybindings.

---

## 2. Forensic Root-Cause Analysis

Inspecting the installed kickstart (`/Volumes/LRMS4/Projects/moonstone-googlebook/iso-extracted/omarchy-ks.cfg`), the Slot B initramfs (`192.168.8.14:/tmp/v_unpack`), `hyprland-0.56.2-19.fc44.x86_64.rpm` (`nett00n/hyprland` COPR), `uwsm-0.27.1-1.fc44.x86_64.rpm`, and the upstream Arch `omarchy` / `omarchy-settings` PKGBUILDs uncovered **five interacting root causes**:

### Root Cause 1: Hyprland `0.56.2-19.fc44` Auto-Generates `~/.config/hypr/hyprland.lua` When Missing, Defeating `[ ! -f ... ]` Checks
In `hyprland-0.56.2-19.fc44` (`src/config/supplementary/jeremy/Jeremy.cpp` and `src/config/lua/ConfigManager.cpp`):
- `Jeremy::getMainConfigPath()` resolves `--config` (explicit), then `$HYPRLAND_CONFIG`, then `~/.config/hypr/hyprland.lua`, then `~/.config/hypr/hyprland.conf`.
- If neither `~/.config/hypr/hyprland.lua` nor `~/.config/hypr/hyprland.conf` exists, `Jeremy::getMainConfigPath()` returns `~/.config/hypr/hyprland.lua` and `CConfigManager::generateDefaultConfig()` **writes an autogenerated stub to `~/.config/hypr/hyprland.lua`** containing `hl.config({ autogenerated = true })` (`src/config/lua/DefaultConfig.hpp`).
- `CConfigManager::postConfigReload()` (line 802) then renders the yellow warning banner at the top of the display:
  > `"Warning: You're using an autogenerated config! Edit the config file to get rid of this message. (config file: /home/jcasco/.config/hypr/hyprland.lua )"`
- **The Self-Healing Trap**: Once Hyprland writes that stub on the first failed boot, `/home/jcasco/.config/hypr/hyprland.lua` **exists on disk as a regular file**. Any subsequent check using `if [ ! -f /home/jcasco/.config/hypr/hyprland.lua ]` (which `googlebook-sysroot-sync` / `googlebook-gpu-init` previously used) evaluates to `false` and **never overwrites the autogenerated stub**.

### Root Cause 2: `omarchy-provision-user` Does Not Seed `~/.config/`
- In the previous `googlebook-gpu-init` script:
  ```sh
  if [ ! -f /home/jcasco/.config/hypr/hyprland.lua ] && [ -d /usr/share/omarchy/config ]; then
    su - jcasco -c "... /usr/share/omarchy/bin/omarchy-provision-user --force --first-install"
  fi
  ```
- As documented in `/usr/share/omarchy/bin/omarchy-provision-user` (lines 12–17), `omarchy-provision-user` *"runs the per-user setup steps that `/etc/skel` can't seed... For shipped configs see `/etc/skel`"*. It **never** copies `/usr/share/omarchy/config/.` into `~/.config/`.

### Root Cause 3: `%post` in `iso-extracted/omarchy-ks.cfg` Omitted Critical System & User Files and Aborted in `mise-work.sh`
Comparing the `iso-extracted/omarchy-ks.cfg` used during installation against the upstream `omarchy` and `omarchy-settings` PKGBUILDs revealed four critical omissions:
1. **Missing `/usr/share/sddm/hyprland.lua`**:
   - `iso-extracted/omarchy-ks.cfg` (lines 435–439) copied `/usr/share/omarchy/default/sddm/omarchy` to `/usr/share/sddm/themes/omarchy`, but **never copied `/usr/share/omarchy/default/sddm/hyprland.lua` to `/usr/share/sddm/hyprland.lua`**.
   - Additionally, `omarchy-fedora/etc/sddm.conf.d/10-wayland.conf` and `omarchy-apply-fedora-patches` (Check 2, line 56) set `CompositorCommand=uwsm start -e -D Hyprland hyprland.desktop` for the SDDM greeter (`sddm` user, `/var/lib/sddm`), which has no `~/.config/hypr/hyprland.lua` and triggers `uwsm`'s 30s `wayland-session-waitenv.service` failure (`OnFailure=wayland-session-shutdown.target`).
   - Even when `googlebook-sysroot-sync` later wrote `CompositorCommand=Hyprland --config /usr/share/sddm/hyprland.lua`, `/usr/share/sddm/hyprland.lua` did not exist on `/sysroot`, so `Hyprland` logged `"Explicit config at /usr/share/sddm/hyprland.lua does not exist, falling back to default logic"` and auto-generated `/var/lib/sddm/.config/hypr/hyprland.lua` (`autogenerated = true`) right on top of the SDDM password screen.
2. **Missing `/usr/bin/omarchy-*` Symlinks and `env-bootstrap` `PATH` Assumption**:
   - `iso-extracted/omarchy-ks.cfg` (lines 427–428) only symlinked `omarchy` and `uwsm-app` into `/usr/local/bin/`, **never symlinking `/usr/share/omarchy/bin/*` into `/usr/bin/`**.
   - However, `/usr/share/omarchy/default/bash/env-bootstrap` (lines 18–26) explicitly skips adding `/usr/share/omarchy/bin` to `PATH` when `OMARCHY_PATH=/usr/share/omarchy` because it assumes `/usr/bin/omarchy-*` symlinks exist from the package manager.
3. **Missing `/usr/share/uwsm/default` and `/usr/share/uwsm/env.d/10-omarchy`**:
   - `iso-extracted/omarchy-ks.cfg` never installed `/usr/share/uwsm/default` or `/usr/share/uwsm/env.d/10-omarchy`, nor `/usr/lib/systemd/user/*.service` or `/etc/profile.d/omarchy.sh`.
   - Furthermore, line 19 of `default/uwsm/env.d/10-omarchy` (`omarchy-cmd-present mise && eval "$(mise activate bash --shims)"`) is the last statement of a sourced script; if `mise` or `omarchy-cmd-present` returns non-zero, `. /usr/share/uwsm/env.d/10-omarchy` returns non-zero unless guarded by `|| true`.
4. **`install/user/mise-work.sh` Hard `exit 1` Aborted `omarchy-provision-user` Midway**:
   - When `omarchy-provision-user --force --first-install` ran in `%post` (under `set -euo pipefail` without `OMARCHY_INSTALL_LOG_FILE`), `install/user/all.sh` sourced `install/user/mise-work.sh`.
   - `mise-work.sh` looked for `/opt/packages/node-v*-linux-x64.tar.gz` (an Arch ISO offline artifact absent on Fedora) and executed `exit 1` (line 29), **aborting `omarchy-provision-user` before `default-keyring.sh`, `mise.sh`, `platform-setup.sh`, `omarchy-refresh-applications`, migration markers, and `omarchy-done mark finalize-user` could run**.

### Root Cause 4: Why It Dropped to a Black Screen with a Cursor (and Got Kicked Out by UWSM)
- In `uwsm-0.27.1-1.fc44`, `wayland-session-waitenv.service` (`ExecStart=/usr/bin/uwsm aux waitenv`, `TimeoutStartSec=30`, `OnFailure=wayland-session-shutdown.target`) waits for `WAYLAND_DISPLAY` and `HYPRLAND_INSTANCE_SIGNATURE` (`UWSM_WAIT_VARNAMES` in `/usr/share/uwsm/plugins/hyprland.sh`) to be exported to the `systemd --user` activation environment.
- In Omarchy, those variables are exported to `systemd --user` **only by `/usr/share/omarchy/default/hypr/autostart.lua` (lines 11–12)**:
  ```lua
  hl.exec_cmd("systemctl --user import-environment $(env | cut -d'=' -f 1)")
  hl.exec_cmd("dbus-update-activation-environment --systemd --all")
  hl.exec_cmd("omarchy-launch-shell")
  ```
- When Hyprland ran with the autogenerated `hyprland.lua` stub instead of Omarchy's `config/hypr/hyprland.lua`, `default/hypr/autostart.lua` never executed:
  1. `omarchy-launch-shell` (`quickshell` bar + `owe` wallpaper engine) never started, leaving **an empty black compositor screen with a mouse cursor**.
  2. `WAYLAND_DISPLAY` and `HYPRLAND_INSTANCE_SIGNATURE` were never exported to `systemd --user`, causing `wayland-session-waitenv.service` / `wayland-wm@hyprland.desktop.service` to fail and terminate the session.

### Root Cause 5: Btrfs `subvol=home` Not Mounted During Initramfs `googlebook-sysroot-sync`
- On Fedora Btrfs (`autopart --type=btrfs`), `/` is `subvol=root` and `/home` is `subvol=home`.
- During `googlebook-sysroot-sync.service` (`Before=initrd-switch-root.target`), only `/sysroot` (`subvol=root`) is mounted by `sysroot.mount`; `/sysroot/home` is an empty directory unless `subvol=home` is explicitly mounted at `/sysroot/home` during the sync step.

## 3. Two-Tier Fix Implemented

### Tier 1: Immediate Self-Healing Boot Fix (`googlebook-sysroot-sync` + `googlebook-gpu-init`)
Updated [`bin/googlebook-sysroot-sync`](file:///Volumes/LRMS4/Projects/googlebook-dualboot/bin/googlebook-sysroot-sync) (and deployed to `root@192.168.8.14:/tmp/v_unpack/usr/bin/googlebook-sysroot-sync`, `/tmp/v_unpack/usr/local/bin/googlebook-sysroot-sync`, and `/tmp/googleboot-iso-build/v_unpack_menu/usr/bin/googlebook-sysroot-sync`) so the existing installation on the Googlebook heals itself automatically on the very next boot:

1. **Mounts Btrfs `subvol=home` at `/sysroot/home` during initramfs** (and unmounts cleanly before `switch-root`) so `/sysroot/home/<user>` is directly accessible in initramfs, in addition to running a second-stage check in `googlebook-gpu-init.service` (`After=local-fs.target home.mount`, `Before=sddm.service`).
2. **Detects all human users (`UID >= 1000 && UID < 60000`) dynamically** from `/sysroot/etc/passwd` (falling back to `jcasco`).
3. **Detects and overwrites Hyprland's autogenerated `hyprland.lua` stub**:
   - Checks `! grep -q "default/hypr/bootstrap.lua" "$user_dir/.config/hypr/hyprland.lua"` (instead of only `[ ! -f ... ]`), removes any stale `hyprland.conf`, and copies `/usr/share/omarchy/config/.` into `$user_dir/.config/`.
4. **Installs all missing system-wide Omarchy files**:
   - Symlinks all `/usr/share/omarchy/bin/*` into `/usr/bin/` and `/usr/local/bin/`.
   - Updates `/usr/share/omarchy/default/bash/env-bootstrap` to always prepend `/usr/share/omarchy/bin` to `PATH` and links `/etc/profile.d/omarchy.sh`.
   - Installs `/usr/share/uwsm/default` and `/usr/share/uwsm/env.d/10-omarchy` (with `|| true` on the `mise activate` line).
   - Installs `/usr/share/sddm/hyprland.lua`, `/usr/share/sddm/themes/omarchy`, `/usr/share/wayland-sessions/omarchy.desktop`, removes `/var/lib/sddm/.config/hypr` and conflicting `/usr/share/wayland-sessions/hyprland-uwsm.desktop`, and configures `/etc/sddm.conf.d/10-wayland.conf` (`CompositorCommand=Hyprland --config /usr/share/sddm/hyprland.lua`), `/etc/sddm.conf.d/autologin.conf`, and `/var/lib/sddm/state.conf`.
   - Patches `omarchy-apply-fedora-patches` Check 2 so it never reverts `10-wayland.conf` to `uwsm start`.
   - Patches `install/user/mise-work.sh` and `install/user/mise.sh` so offline runs never `exit 1`.
5. **Pre-seeds the `Tokyo Night` theme (`~/.local/state/omarchy/current/theme`, `theme.name`, `background` symlink) and migration markers** directly in `$user_dir/.local/state/omarchy/` and runs `omarchy-provision-user --force --first-install` in `googlebook-gpu-init` before `sddm.service` starts.

### Tier 2: Permanent Zero-Touch Installer Fix (`omarchy-ks.cfg` + `fedomakase-googlebook-slotb`)
1. **[`patches/omarchy-ks.cfg`](file:///Volumes/LRMS4/Projects/googlebook-dualboot/patches/omarchy-ks.cfg)**:
   - `%pre` stages `/tmp/omarchy-fedora` so Anaconda repo mounts cannot shadow the payload before `%post --nochroot`.
   - `%post --nochroot` checks `/tmp/omarchy-fedora`, all `/run/install/*` paths, and falls back to downloading `$STAGE2_URL/omarchy-fedora.tar.gz` via HTTP.
   - `%post` (chroot) installs all `/usr/bin/omarchy-*` symlinks, `/etc/profile.d/omarchy.sh`, `/usr/share/uwsm/{default,env.d/10-omarchy}`, `/usr/share/sddm/hyprland.lua`, complete `/etc/skel` files, pre-seeds `Tokyo Night` in `~/.local/state/omarchy/current/`, and patches `omarchy-apply-fedora-patches`, `mise-work.sh`, and `mise.sh` before running user provisioning.
2. **[`bin/fedomakase-googlebook-slotb`](file:///Volumes/LRMS4/Projects/googlebook-dualboot/bin/fedomakase-googlebook-slotb)**:
   - Automatically embeds `googlebook-sysroot-sync` and `googlebook-sysroot-sync.service` into `rd_vendor` whenever Slot B is packed during `%post` or kernel upgrades.
